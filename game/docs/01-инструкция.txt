Я делаю игру НЕ как отдельный готовый продукт, а как модуль для уже существующего Telegram Mini App.

Основной проект уже существует. Его backend работает на Cloudflare Workers + D1, а интерфейс открывается внутри Telegram Mini App.

Твоя задача сейчас — сделать ТОЛЬКО САМУ ИГРУ. Не пытайся самостоятельно переделывать существующего Telegram-бота, базу данных, авторизацию или основной сайт.

После этого другой разработчик встроит игру в существующий проект.

ВАЖНЫЕ ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

1. Игра должна работать в браузере внутри Telegram Mini App на iPhone и Android.

2. Предпочтительно использовать обычные:
- HTML
- CSS
- JavaScript

Без React/Vite/Next.js и сложной сборки, если они реально не нужны.

3. Все файлы игры должны лежать отдельно, например:

/game/

Внутри:

index.html
game.css
game.js
/assets/

Можно создавать дополнительные JS-файлы, если игра большая.

4. Все картинки, фоны, предметы, звуки и прочие ресурсы должны находиться локально в папке assets.

НЕ используй временные ссылки, внешние хостинги изображений или ресурсы, которые могут исчезнуть.

5. Игра должна автоматически адаптироваться под экран телефона.

Особенно под вертикальный экран iPhone.

6. Не использовать emoji вместо нормальных игровых элементов или иконок.

7. Игра должна запускаться простым открытием game/index.html.

8. Сделай возможность запуска игры в DEMO-режиме без Telegram, чтобы разработчик мог открыть её обычным браузером и проверить.

СИСТЕМА ПОБЕДЫ

В игре будут реальные внутренние деньги Family Bank.

НЕЛЬЗЯ начислять деньги прямо через JavaScript игры, localStorage или изменением цифры баланса на клиенте.

Игра должна только сообщать основному приложению, что раунд закончен победой.

Сделай единую функцию, например:

window.FamilyBankGame.win(data)

или другой очень простой единый интерфейс.

Пример данных:

{
  game: "game_id",
  roundId: "уникальный_id_раунда",
  result: "win"
}

Размер денежной награды НЕ должен определяться клиентом.

Награду после интеграции будет определять backend Family Bank.

Также сделай событие проигрыша:

{
  game: "game_id",
  roundId: "...",
  result: "lose"
}

Если игре требуется дополнительная информация для проверки победы, можешь добавить поле proof.

ЗАЩИТА

Не делай так, чтобы пользователь мог получить деньги простым вызовом:

win()

из консоли браузера.

Полноценную серверную проверку позже сделает другой разработчик, но архитектура игры должна позволять проверять результат на сервере.

Поэтому отдельно напиши, какие данные backend должен сохранять при начале раунда и какие данные игра должна отправлять при завершении.

ИНТЕГРАЦИЯ

Создай файл:

INTEGRATION.md

В нём максимально понятно опиши:

- какой файл открывает игру;
- какие файлы обязательны;
- как основной сайт запускает новую игру;
- как узнать о победе;
- как узнать о проигрыше;
- какие данные передаются при победе;
- какие данные необходимы backend для защиты от повторного получения награды;
- какие глобальные функции/API использует игра;
- какие параметры можно менять;
- где менять размер карты, количество объектов, сложность и т.д.;
- какие внешние библиотеки используются, если они вообще используются.

Также создай:

GAME_CONFIG.md

где перечисли все игровые настройки.

ОЧЕНЬ ВАЖНО

Не создавай фальшивый backend.

Не создавай отдельную регистрацию.

Не создавай отдельного Telegram-бота.

Не создавай собственную систему денег.

Не создавай отдельный аккаунт игрока.

Это всё уже существует в основном приложении.

Ты делаешь исключительно игру и понятный интерфейс для её подключения.

ФИНАЛЬНЫЙ РЕЗУЛЬТАТ

Когда закончишь:

1. Проверь игру полностью.
2. Проверь консоль браузера — не должно быть ошибок.
3. Проверь мобильную адаптацию.
4. Проверь несколько полных игровых раундов.
5. Проверь победу и проигрыш.
6. Удали ненужные тестовые файлы.
7. Не оставляй TODO, заглушки или недоделанные элементы.

После этого собери ВСЁ в один архив:

family-bank-game.zip

Я должен иметь возможность просто передать этот ZIP другому разработчику, и он должен понять проект без дополнительных объяснений.

Не присылай мне 20 отдельных кусков кода вместо архива.

Если твоя среда позволяет создавать файлы — дай именно готовый ZIP.
